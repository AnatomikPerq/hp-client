# Нестандартные протоколы

Здесь лежат бинарники протоколов, которые HYPER CLIENT запускает рядом с
ядром. Каталог **под контролем версий намеренно**: клиент задуман как дом для
транспортов, которых не понимают обычные клиенты, и сборка из чистого клона
обязана получать их сама — без ручной подкладки файлов.

## Раскладка

```
protocols/<протокол>/<платформа>/<архитектура>/<бинарник>
```

Сборка ставит их рядом с ядром, в подкаталог `bin/` готового приложения.
Прописано в `windows/app.cmake` (и в `linux/app.cmake`, когда появятся
Linux-сборки протоколов).

## Как добавить протокол

1. Положить бинарник по схеме выше.
2. Добавить `install(PROGRAMS ...)` в `app.cmake` нужных платформ.
3. Описать в разделе ниже: что это, откуда, под какой лицензией.
4. Реализовать разбор ссылок и запуск в `lib/service/<протокол>/`.
   Разбирать ссылки нужно **в Dart, до libXray** — ядро чужих схем не знает
   и молча их выбрасывает, а править libXray нельзя: это превратит
   обновление апстрима в ручное слияние.

## Что здесь сейчас

### minewire

Транспорт, маскирующий трафик под игровой протокол Minecraft. Поднимает
локальный SOCKS5, к которому клиент подключается обычным `socks`-outbound.
Права администратора не требуются.

- **Ссылки:** `mw://<пароль>@<хост>:<порт>?mode=<режим>&proxy=socks5#<имя>`
- **Автор:** сторонний, не входит в состав HYPER CLIENT как его часть.
- **Версия:** `minewire-cli core v26.7.3`
- **Платформы:** Windows x64

Бинарник распространяется вместе с клиентом как отдельная программа: он
запускается своим процессом и общается с клиентом через локальный сокет.
Подробности о правовом статусе — в `LICENSE-THIRD-PARTY.md` в корне.
